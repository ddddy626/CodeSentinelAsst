## 实测命令与范围

在 `backend`：`uv run --locked python -m pytest -q` 得到 28 passed；`python -m app.evaluate` 得到 12 cases、8 TP、0 FP、0 FN。`frontend`：`npm run build` 通过。另用真实本机 Redis、临时 SQLite、FastAPI TestClient 与 Worker 完成一次任务，结果是 `completed`、`request_changes`、7 条事件、SSE `done`。

模型对照采用 `python -m app.ablate --dataset evaluation/ablation_cases.json --with-model --context-budget 300 --out evaluation/results/ablation-live.json`。标注集 SHA256、模型名、提示词哈希、扫描器版本、原始报告、每例预测与覆盖缺口都写在结果文件。A/B/C/D 的耗时分别约 15.6、78.0、177.8、154.2 秒；它们是当次本机墙钟时间，不是稳定性能基准。D 组选取源码 1526 字符，C 组 3382 字符，减少约 55%；未测 Token，也未观察到这组样本的检出率变化。

## 仍需补证据

1. 在装有 Docker 的机器上执行 `docker compose up --build -d`，检查 MySQL 8.4、Redis 7、API、Worker、Web 的实际连通与重启恢复。
2. 浏览器实测 UTF-8/非法编码上传、登录、项目隔离、任务取消、SSE 断线重连。
3. 建立来自真实项目的人工标注集，覆盖安全、逻辑、边界和正常代码，再比较 A/B/C/D。当前 16 个样本全为合成数据，A 已满分，不能推断模型没有价值或线上效果。
4. 多 Worker 租约、数据库迁移和公开部署安全加固目前不在本地单 Worker V1 的运行证据内。
